## セットアップ

```bash
npm install
cp .env.example .env.local   # AI補助を使う場合のみ
npm run dev
```

http://localhost:3000 で確認。

### AI補助について

`.env.local` に鍵を書くとモデル経由になり、未設定なら端末の中だけで動く
簡易版が使われます。

```
ANTHROPIC_API_KEY=sk-ant-...
AI_MODEL=claude-haiku-4-5-20251001
```

**どちらの場合も本文生成・表紙生成は行いません。**
指示文そのものが存在しないので、設定でオンにすることもできません
（`src/lib/ai/prompts.ts` を参照）。

鍵はサーバー側だけで使い、ブラウザへは出しません
（`src/app/api/ai/` の 3 つのルートを必ず経由します）。

**いま繋がっているかは画面で分かります。**
資料の左下と、設定の「AI補助設定」に接続状態が出ます。

**送る量を抑える工夫**

- 自動抽出はいま書いている 1 話だけを送り、10 分に 1 回までに絞っています
- 手動の「本文から資料を集める」は「最近の話（末尾3話）」が既定です
- サーバー側でも 40,000 字で切ります。切るのは古い側で、いま書いている場面は残します

**失敗しても止まりません。** モデルが使えないときは簡易版へ落ちて候補を出し、
理由を画面に添えます（黙って質が落ちると原因が分からないため）。

## ファイル構成

```
src/
├── app/                       # 画面・ルーティング（page / layout / route のみ）
│   ├── page.tsx               # 作品一覧
│   ├── workspace/[workId]/    # 執筆画面
│   ├── workspace/[workId]/settings/  # 設定画面
│   ├── layout.tsx
│   └── globals.css            # デザイントークン（CSS変数）
├── components/                # UIコンポーネント（機能単位・kebab-case）
│   ├── layout/                # header
│   ├── works/                 # 作品一覧・作品作成・タグ入力
│   ├── workspace/             # 執筆画面（話一覧・エディタ・履歴・資料リンク）
│   ├── settings/              # 設定画面（作品情報・公開・表示・原稿管理）
│   └── resource/              # 資料（人物・場所・関係図・時系列・プロット）
├── config/                    # 設定値の一元管理
├── hooks/                     # use-works / use-episodes / use-autosave
├── lib/
│   ├── repository/            # ★ データ保存先の抽象化層
│   │   ├── types.ts           #   インターフェース定義
│   │   ├── local-repository.ts#   localStorage 実装（v1）
│   │   └── index.ts           #   ここ 1 か所で実装を切り替える
│   └── utils/                 # id / text
└── types/                     # 型定義（Supabaseのカラム名と1:1）
docs/DATA_MODEL.md             # データモデル設計メモ
supabase/migrations/           # v2 で使う DB スキーマ
```

### 構成ルール

- `app/` には `page.tsx` / `layout.tsx` / `route.ts` などのルートファイルのみを置く。UI は `components/` へ
- ファイル名は kebab-case、コンポーネント名は PascalCase
- import は `@/` エイリアスのみ使用（相対 import は使わない）
- 環境変数は `process.env` を直接参照せず `config/` 経由で利用する
- **データの読み書きは必ず `getRepository()` 経由**。localStorage や Supabase を画面側から直接触らない

## 次にやること（優先度順）

1. **ゴミ箱** — 削除の取り消し。いまは消したら戻せない
2. **整合性チェック** — 資料と本文の突き合わせ（本文に出ない人物、資料に無い固有名詞）
3. **自動バックアップ** — File System Access API でフォルダを一度選ばせる
4. **画像・ファイルの保存** — 図案はいまデータURIで持っている。Supabase Storage へ移す
4. **予約投稿の実行** — いまは日時を保存するだけ。切り替えにはサーバー側の処理が要る
5. **Supabase 移行とログイン** — 手順は `docs/DATA_MODEL.md` の 4 を参照

## バックアップ

作品一覧の「バックアップ」から、すべての作品・原稿・資料・設定を
1 つの JSON にまとめて取り出せます。7日以上あくと画面上で知らせます。

戻すときは 2 通り。

- **足す** … いまのデータを残し、バックアップにしか無いものだけ入れる（上書きしない）
- **置き換える** … いまのデータを消してから入れる

形式には版番号が入っていて、新しい形式のファイルを古いアプリで開こうとすると止まります。

## 注意点

- **PDF の読み込み**は `pdfjs-dist` を使います。PDF は文字の位置情報しか持たないため、
  改行や段落が原稿どおりに戻らないことがあります。取り込み後の手直しを前提にしてください。
- **PDF の書き出し**は生成ライブラリを使わず、印刷用ページを開いてブラウザの
  「PDF として保存」に渡します。日本語フォントの埋め込みと縦書きの両方を
  標準機能で扱えるためです。ポップアップの許可が必要です。

## 本文の記法

ルビと傍点だけは本文に埋め込みます。**これまでの「本文は素のテキスト」という
方針の唯一の例外**です。「どの文字にどう読ませるか」は文字の並びと不可分で、
位置を別テーブルに持つと本文を1文字直すたびに全部ずれるためです。

```
｜原石《げんせき》   親文字を指定する
原石《げんせき》     直前の漢字の連なりに振る
《《ここ》》          傍点
```

記法は日本語の投稿サイトで広く使われているものに合わせています。独自記法にすると、
書き手が他所から持ってきた原稿が壊れます。

**文字数は親文字だけを数えます。** ルビは読みであって本文ではないので、
ルビを振るたびに文字数が増えるのはおかしいためです。
